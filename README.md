# TaxOffice Hub

세무사무실 거래처 관리 웹앱입니다. 배포하면 어떤 컴퓨터에서든 사이트 주소로 접속해서 사용할 수 있습니다.

## 기장료 관리

거래처 관리 메뉴의 **기장료 관리**에서 매입매출장 엑셀을 가져옵니다. 월별 수금·미수 현황은 품명의 대상 월 기준이며, **7월~6월 총정산과 담당자별 매출은 발행일 기준**입니다. 2024년 귀속 조정료를 2026년 7월에 발행하면 2026.07~2027.06 매출 정산에 포함합니다. 귀속연도는 참고 정보로 별도 보관합니다.

연도 없는 기장료 품명은 제안된 연도를 확인해야 하며, 여러 달 청구는 월별 분리 후 원본 금액과 합계가 일치해야 저장됩니다. 조정료·기타 수수료의 대상 월은 발행 월로 제안합니다. 가져오기 화면의 전체 체크·전체 해제는 모든 페이지에 적용됩니다. 대상 월 누락, 귀속연도 미지정 조정료, 분리 전 내역은 전체 체크에서도 확인되지 않습니다.

청구는 사업자번호로 기존 거래처와 연결합니다. 미등록 거래처 화면에서 기존 거래처에 연결하거나 등록 양식을 열 수 있습니다. 폐업·이관 거래처의 기존 청구는 유지합니다. 담당자별 매출은 원본 부서명 기준이며 상여율은 적용하지 않습니다.

입금은 거래처 행을 눌러 청구별 실제 입금일과 금액을 등록합니다. 자료가 없는 거래처는 입금 확인 필요로 표시합니다. 통장 내역을 확인한 뒤 현재 목록의 입금 대조 완료를 누르면 잔액을 미수금으로 표시합니다. 기간 이전 청구 잔액은 이 기간 정산에 합산하지 않습니다. 음수 전표는 청구 차감으로 포함합니다.

자료는 기존 Supabase `app_state` 테이블의 `billingLedgerV1` 키로 저장됩니다. 새 테이블 설치는 필요하지 않습니다. 실제 세금계산서 발행이나 은행 내역 자동 수집은 이 기능에 포함되지 않습니다.

계산 및 품명 인식 검증: `node --test src/lib/billing.test.js`

**조정료 관리** 탭은 발행일 기준으로 조정료만 조회하고 직접 등록합니다. `3~5월 기장료, 2025년 귀속 조정료`처럼 합산된 품명은 가져오기 화면에서 **기장료 + 조정료 분리**를 눌러 기장료 월별 행과 조정료 1개 행으로 구분합니다. 금액을 자동으로 균등 분배하지 않으며, 각 행의 공급가액·부가세를 직접 입력해야 합니다. 분리 합계는 원본과 일치해야 저장됩니다. 이미 저장한 합산 청구는 자동 재분리하지 않습니다.

가져오기 화면은 기본으로 확인 필요한 내역만 표시합니다. 명확한 연도·월 또는 발행 월에서 2개월 이내의 같은 연도 기장료는 별도 체크 없이 저장 가능합니다. 연도 경계, 오래된 대상 월, 금액 수정, 여러 달 분리 내역은 직접 확인합니다. 확인 체크만으로 공용 저장되지는 않으며 저장 버튼을 눌러야 합니다. 저장 성공 후 처리된 내역은 검토 목록에서 빠지고, 저장한 청구의 대상 월에 맞춰 조회 기간·월이 변경됩니다.

## 운영 준비

1. Supabase SQL Editor에서 `supabase-app-state.sql` 내용을 실행합니다.
2. Vercel에 이 프로젝트를 연결합니다.
3. Vercel 환경변수에 아래 값을 넣습니다.

```text
VITE_SUPABASE_URL=Supabase Project URL
VITE_SUPABASE_ANON_KEY=Supabase anon/public key
```

## 배포 설정

Vercel이 Vite 앱으로 자동 인식합니다.

```text
Build Command: npm run build
Output Directory: dist
```

배포 후 받은 주소로 접속하면 바로 앱이 열립니다. 크롬이나 엣지에서 사이트를 연 뒤 브라우저 메뉴의 앱 설치 기능을 쓰면 바탕화면 아이콘처럼 실행할 수 있습니다.

## 참고

로그인을 쓰지 않는 설정이라 사이트 주소와 Supabase 키가 노출되면 다른 사람도 데이터에 접근할 수 있습니다. 혼자 쓰고 주소를 공유하지 않는 용도라면 가장 간단하고, 나중에 직원이 늘어나면 로그인 방식으로 다시 바꾸는 편이 좋습니다.
